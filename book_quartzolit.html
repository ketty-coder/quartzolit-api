02 · MODELO DE DADOS

Tabelas Fato

f_faturamento

Fonte: SAP

Granularidade: item de pedido/NF

  • Referência Temporal (join calendário)
  • Agrupamento Nível 1/2/3 (família)
  • Estado, Cliente, Canal, Regional
  • Quantidade, Faturamento Líquido
  • YPR0, ZLIP, Rebates, Descontos
  • FK_Custos, FK_BRInsights

f_custos

Fonte: Planilha RBE

Granularidade: material × mês × fábrica

  • Mês de Apuração Custo
  • Código Produto / Material Nome
  • Fábrica de Produção
  • Custo RBE (usado na margem)
  • Custo MPE
  • PK_Custos (chave primária)

f_brinsights

Fonte: BRInsights

Granularidade: produto × PDV × semana

  • Data da Coleta / Semana
  • CODEAN, Material, Família
  • Marca do Fornecedor (concorrente)
  • Preço Sell Out
  • Estado, Cliente/Bandeira
  • PK_BRInsights (chave primária)
⚠️ Chaves compostas foram necessárias pois não há uma única coluna para join:
FK_Custos = Código Produto + AAAAMM + Fábrica  |  FK_BRInsights = Agrupamento Nível 3 + AAAAsemana

03 · REGRAS DE NEGÓCIO

Classificação Semáforo — P10/P90 Dinâmico

A chave de análise é Família (Agrupamento Nível 1) × UF. Cada combinação recebe um Score Final e é classificada dinamicamente.
🟢
VERDE — Saudável

Score Final ≤ P10
Dentro do percentil 10 das melhores chaves

🟡
AMARELO — Atenção

P10 < Score < P90
Região intermediária — monitorar

🔴
VERMELHO — Crítico

Score Final ≥ P90
Piores 10% das chaves — ação imediata

Por que P10/P90 e não thresholds fixos?

Os percentis são calculados dinamicamente sobre todas as chaves ativas (com ALL(d_uf) para estabilidade). Isso garante que sempre haja ~10% de chaves Vermelhas e ~10% Verdes, independente do período ou contexto — o semáforo reflete a posição relativa, não um valor absoluto.

03 · REGRAS DE NEGÓCIO

Ponto de Ataque — Diagnóstico T1 / T2 / T3

T1 — Problema de PREÇO

Dispara quando Preço Sell IN caiu

Causas possíveis:
  • 1A — Tabela caiu: planejado ou pressão?
  • 1B — Desconto excessivo corrói preço realizado

T2 — Problema de VOLUME

Dispara quando Volume caiu

Causas possíveis:
  • 2A — Queda estrutural de mercado
  • 2B — Reajuste gerou fuga de volume
  • 2C — Perda estrutural go-to-market

T3 — Problema de RENTABILIDADE

Dispara quando Margem caiu

Causas possíveis:
  • 3A — Margem comprimida por custo
  • 3B — Rebates absorvendo margem
  • 3C — Mix desfavorável

⚠️ Deterioração Sistêmica — Nível Crítico Máximo

Ocorre quando T1 + T2 + T3 disparam simultaneamente na mesma chave (Família × UF). Indica problema estrutural grave: preço caiu, volume caiu E margem caiu ao mesmo tempo. Ação imediata necessária.

04 · CHAT IA

Arquitetura do Chat — 3 Endpoints

POST /api/chat

Motor principal. Dois modos:

  • gerar_dax Converte pergunta em DAX
  • gerar_grafico Converte dados em Chart.js config
  • chat Resposta contextualizada via Claude

POST /api/query

Executa DAX diretamente no modelo semântico Power BI via REST API com token Azure AD.

  • Autentica via Client Credentials
  • Chama executeQueries endpoint
  • Retorna linhas brutas

GET /api/dados

Busca KPIs + Top 5 alertas para contexto inicial.

  • Receita, Volume, Margem, Preço
  • Score verde/amarelo/vermelho
  • Top 5 famílias com alerta

Variáveis de Ambiente

ANTHROPIC_API_KEY TENANT_ID CLIENT_ID CLIENT_SECRET WORKSPACE_ID DATASET_ID
04 · CHAT IA

Fluxo Completo de uma Consulta com Dados

1. Usuário digita a pergunta

Ex: "Gere um gráfico com o faturamento mês a mês em 2025"

2. Frontend detecta que precisa de dados

Regex verifica palavras-chave (faturamento, mês, 2025, família, UF...)

3. POST /api/chat — action: "gerar_dax"

Claude recebe o SCHEMA completo + pergunta → gera DAX correto em <3s

4. POST /api/query — executa DAX no Power BI

Azure AD token → Power BI executeQueries → retorna linhas de dados reais

5. Se pediu gráfico → POST /api/chat — action: "gerar_grafico"

Claude converte os dados em config Chart.js: type (bar/line/pie), labels, datasets

6. Resposta exibida no chat

Texto formatado com **negrito** OU gráfico Chart.js renderizado inline · Botão "Exportar PDF" disponível

04 · CHAT IA

O SCHEMA — Como a IA conhece o modelo Power BI

O system prompt do Claude contém o SCHEMA completo do modelo semântico. Isso dá à IA conhecimento preciso para gerar DAX correto sem erros.

O SCHEMA inclui:

  • Lógica de negócio (Score, P10/P90, T1/T2/T3)
  • Todas as tabelas e colunas exatas
  • 99 medidas com descrição
  • 15+ exemplos DAX por tipo de pergunta
  • Regras críticas de sintaxe DAX
-- Exemplo CERTO ✅ EVALUATE CALCULATETABLE( SUMMARIZECOLUMNS( d_calendario[Ano-Mês], d_calendario[Mês Nome], "Fat", [Faturamento Pocket] ), d_calendario[Ano] = 2025 ) -- Exemplo ERRADO ❌ EVALUATE SUMMARIZECOLUMNS( d_calendario[Ano-Mês], d_calendario[Ano] = 2025, ← ERRADO [Faturamento Pocket] ← sem "Nome" )
04 · CHAT IA

O que é cada tecnologia da infraestrutura

⚡ Vercel

Plataforma de hospedagem em nuvem especializada em funções serverless e frontends. Não exige servidor dedicado — o código roda apenas quando há uma requisição e "dorme" quando ocioso. Integrado com GitHub: qualquer git push na branch main gera um novo deploy automático em produção em ~30s.

  • URL pública: quartzolit-api-6a8h.vercel.app
  • Funções: /api/chat · /api/query · /api/dados
  • Runtime: Node.js 18 · 256 MB RAM · timeout 30s

🤖 Anthropic Claude Haiku 4.5

Modelo de linguagem (LLM) da Anthropic — empresa de IA fundada ex-OpenAI. Haiku é a versão mais rápida e econômica da família Claude, ideal para tarefas estruturadas como geração de DAX. O modelo recebe um system prompt com todo o schema do Power BI e responde em <3 segundos.

  • API REST: api.anthropic.com/v1/messages
  • Cobrado por tokens (unidades de texto processadas)
  • Haiku = mais barato da linha Claude

🔑 Azure AD — Client Credentials

Serviço de identidade da Microsoft. Usamos o fluxo Client Credentials: o backend se autentica como "aplicação" (não como usuário) usando Client ID + Secret para obter um token OAuth 2.0. Com esse token é possível chamar a REST API do Power BI sem login manual.

  • Token expira a cada 3600s (renovado automaticamente)
  • Permissão necessária: Dataset.ReadWrite.All
  • Registrado no portal: Entra ID > Registros de App

📊 Power BI REST API

API oficial da Microsoft que permite executar consultas DAX diretamente no modelo semântico publicado no Power BI Service. O endpoint executeQueries recebe uma string DAX e retorna os dados como JSON — exatamente o que o chat precisa para buscar dados reais do modelo.

  • Endpoint: api.powerbi.com/v1.0/myorg/groups/{'{'}WORKSPACE{'}'}/datasets/{'{'}DATASET{'}'}/executeQueries
  • Retorna: array de linhas com colunas nomeadas
  • Incluída na licença Power BI Pro/Fabric

🐙 GitHub

Plataforma de versionamento de código (Git). O repositório ketty-coder/quartzolit-api armazena todo o código-fonte do projeto. A integração Vercel ↔ GitHub garante CI/CD automático: commit na branch main → Vercel detecta → build → deploy em produção.

  • Branch: main (produção)
  • Segredo: variáveis de ambiente ficam APENAS no Vercel, nunca no repositório
  • Script deploy.ps1: git push + ajuste de alias automático

📈 Chart.js

Biblioteca JavaScript open-source para criação de gráficos interativos no navegador. Versão 4.4.0 carregada via CDN (sem instalação). Quando o usuário pede "gráfico", o Claude gera um JSON de configuração Chart.js que é renderizado diretamente dentro do chat no Power BI.

  • Tipos suportados: bar / line / pie
  • Cores Quartzolit: #FAA954 (amarelo) e #000
  • Gratuito — licença MIT
